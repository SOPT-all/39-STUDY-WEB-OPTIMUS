05 · PART 1 커밋 컨벤션로컬

커밋하는 순간
바로 막아요

  • git 의 commit-msg 훅 — 커밋이 만들어지기 직전에 실행되는 스크립트예요.
  • 규칙에 안 맞으면 커밋 자체가 안 만들어져요.
  • 클론 후 딱 한 번:
    git config core.hooksPath .githooks
  • 셸 스크립트라 npm install 없이 동작해요.
$ git commit -m "수정함"
❌ 커밋 메시지가 컨벤션에 맞지 않아요.

  입력: 수정함

  형식: {type}: {작업 내용}
  type: feat, fix, refactor, docs, chore
  예시: feat: PR 생성 시 리뷰어 자동 할당 …

$ git commit -m "fix: 스레드 중복 생성 수정"
[auto/... 1a2b3c4] fix: 스레드 중복 생성 수정

07 · PART 1 커밋 컨벤션설계

규칙은 한 곳에만

# .githooks/commit-msg
TYPES="feat|fix|refactor|docs|chore"

if [[ "$HEADER" =~ ^($TYPES)(\(.+\))?!?:\ .+ ]]; then
  exit 0
fi
echo "❌ 컨벤션에 맞지 않아요"; exit 1


# CI: PR 커밋마다 같은 파일을 실행
for sha in $(git rev-list --no-merges base..head); do
  bash .githooks/commit-msg "$sha 메시지"
done
  • 보통은 로컬 = husky + commitlint, CI = commitlint-action 처럼 설정이 두 벌이 돼요.
  • 여기선 훅 스크립트 하나를 CI 도 그대로 실행해요.
  • type 을 추가하고 싶으면 TYPES 한 줄만 고치면 로컬 · CI 에 동시에 반영돼요.
08 · PART 2 릴리즈 자동화버전 규칙

커밋 type 이 곧 버전 규칙

커밋의미버전 변화릴리즈 노트
feat! / BREAKING CHANGE호환이 깨지는 변경1.0.0 → 2.0.0⚠ BREAKING CHANGES
feat기능 추가1.0.0 → 1.1.0✨ 새로운 기능
fix refactor docs수정 · 개선1.0.0 → 1.0.1🐛 · ♻️ · 📝
chore설정 · 기타변화 없음표시 안 함

사람이 버전을 고민할 필요가 없어요. 커밋을 규칙대로 쓰는 것만으로 버전이 정해져요.

release-please 는 GitHub Actions 봇 권한으로 릴리즈 PR 을 만드는데, 조직이 이걸 막고 있었어요.

🎁 덤: 봇이 만든 PR 은 다른 워크플로를 실행시키지 않는데(무한루프 방지), 토큰으로 만들면 릴리즈 PR 에도 디스코드 PR 알림 · 컨벤션 검사가 돌아요.

13 · 트러블슈팅 ②

공용 test 브랜치에서 생긴 일

# Week 1 Main PR 이 아직 리뷰 중인데
main  ── 처음 상태
test  ── Week 1 ── Week 3 머지

# Week 1 Main PR (test → main) 에
# Week 3 까지 섞여버림 😱

# 해결: main · test 를 처음 상태로 되돌리고
git push --force-with-lease=test:<현재> \
  origin 9926475:test
# Week 1(#7) · Week 3(#6) 를 auto → test 로 다시 올림
  • test 를 모두가 같이 쓰다 보니, 앞 주차 Main PR 이 머지되기 전에 다음 작업이 들어가면 섞여요.
  • revert 로 되돌리면 나중에 릴리즈 노트에 같은 항목이 두 번 찍혀서, 히스토리를 되돌리는 쪽을 택했어요.
  • 교훈: Main PR 머지 → 다음 주차 test 머지 순서를 지키기
